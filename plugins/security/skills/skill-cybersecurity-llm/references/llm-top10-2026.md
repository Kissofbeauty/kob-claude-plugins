## LLM01:2026 — Prompt Injection
input ผู้ใช้/ข้อมูลภายนอก (เว็บ, เอกสาร, RAG, tool response, MCP resource) แทรกคำสั่งที่เปลี่ยนพฤติกรรมโมเดล — รวม **indirect injection** ผ่าน content ที่โมเดลอ่าน และ injection ที่ซ่อนใน package/README เล็ง coding agent (เคส "Hades" บน PyPI 2026)
- ตรวจ: user input / tool output ต่อตรงเข้า prompt โดยไม่แยกชั้น, ไม่มี instruction hierarchy, agent อ่าน content ภายนอกแล้ว act ทันที
- ✅ แยก system/user/tool, treat tool output เป็น untrusted, จำกัดสิทธิ์, allowlist action, human approval สำหรับ action ที่กลับไม่ได้

## LLM02:2026 — Sensitive Information Disclosure
โมเดลเผย PII/secret/ข้อมูลภายใน (จาก training/context/RAG/memory) ออกไปใน response หรือส่งไป tool/third-party
- ตรวจ: ใส่ secret/PII เข้า prompt/context ตรง ๆ, ไม่มี output filtering/redaction, log prompt ทั้งก้อน

## LLM03:2026 — Excessive Agency ⬆ (จุดเสี่ยงสูงสุดของยุค agent)
agent/tool มีสิทธิ์/ฟังก์ชัน/autonomy เกินจำเป็น → โมเดลถูกหลอก (ผ่าน LLM01) ให้ทำ action อันตราย: ลบไฟล์, จ่ายเงิน, ส่งเมล, push code, เรียก API ภายใน
- ตรวจ: tool definition ที่กว้าง (shell/exec/filesystem ทั้งเครื่อง), credential ของ tool เป็น admin/long-lived, ไม่มี human-in-the-loop, agent loop ไม่มี step/budget cap, MCP server ที่ให้ write/delete โดยไม่ confirm
- ✅ least privilege ต่อ tool, read-only by default, scoped/short-lived credential, approval gate ก่อน irreversible action, sandbox สำหรับ code execution

## LLM04:2026 — Supply Chain
โมเดล/dataset/adapter/plugin/MCP server/skill จากแหล่งไม่น่าเชื่อถือ, model จาก hub ที่ไม่ verify, dependency ของ AI stack มี CVE หรือถูก compromise (LiteLLM, mistralai, guardrails-ai บน PyPI 2026)
- เชื่อมกับ `skill-cybersecurity-supply-chain` + `security-advisory-digest-2026.md`
- ตรวจ: MCP server / skill / plugin ติดตั้งจาก URL/registry ที่ไม่ pin version/hash, model weight ไม่มี checksum

## LLM05:2026 — Data and Model Poisoning
training/fine-tune/RAG data ถูกวางยา → bias/backdoor/คำสั่งแฝง
- ตรวจ: แหล่ง data ที่รับเข้า RAG/training มี validation/provenance ไหม, ใครเขียน vector store ได้บ้าง

## LLM06:2026 — Unbounded Consumption ⬆
ไม่มี limit ต่อ request/token/cost/agent step → DoS, ค่าใช้จ่ายพุ่ง, model extraction · agent loop วนไม่จบ
- ✅ rate limit, token/budget cap ต่อ user และต่อ task, max iterations, timeout, quota, alert ค่าใช้จ่าย

## LLM07:2026 — Misinformation
โมเดล hallucinate ข้อมูล/โค้ด/package ที่ไม่มีจริง (slopsquatting) แล้วถูกนำไปใช้ตัดสินใจ/ติดตั้ง
- ✅ grounding/citation, human review สำหรับ high-stakes, verify package ที่ agent เสนอก่อนติดตั้ง

## LLM08:2026 — Hidden Context Exposure (เดิม System Prompt Leakage)
สิ่งที่โมเดล "เห็นแต่ผู้ใช้ไม่ควรเห็น" รั่ว: system prompt, retrieved document ของคนอื่น, memory, user profile, tool response, app state, internal reasoning
- ตรวจ: secret/business rule ใน system prompt, RAG คืน chunk ข้าม tenant, tool response ที่มี PII ถูกส่งต่อให้ user ทั้งก้อน, debug/trace endpoint เปิดใน prod
- ✅ อย่าใส่ secret ใน context, ถือว่า context ทั้งหมดอาจรั่วเสมอ, filter output ตาม permission ของผู้ถาม

## LLM09:2026 — Vector and Embedding Weaknesses (RAG)
embedding/RAG: data leak ข้าม tenant, ไม่ filter ตาม permission ตอน retrieve, injection ผ่านเอกสารใน vector store, embedding inversion
- ✅ access control ที่ retrieval layer, แยก namespace ต่อ tenant, sanitize เอกสารก่อน index

## LLM10:2026 — Improper Output Handling (ขยาย scope)
เอา output ของโมเดลไปใช้ต่อแบบไม่ sanitize → **RCE/SQLi/XSS/SSRF** รวม sink ใหม่: **terminal command ที่ coding agent รัน, ไฟล์ที่ IDE agent เขียน, git commit/push, config ที่ agent แก้**
- ❌ `exec(llm_output)`, `db.query(llm_output)`, render HTML จาก output ตรง ๆ, รัน shell command ที่โมเดลสร้างโดยไม่ allowlist
- ✅ treat output เหมือน untrusted user input เสมอ (validate/escape/parameterize/allowlist command), sandbox + diff review ก่อน apply
