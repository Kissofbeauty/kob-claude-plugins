# precompact — บันทึก state ก่อน Compact

Compact แล้ว PM มักลืม: flow ที่เดินอยู่, กฎที่ user เคาะไว้กลางบทสนทนา, วิธีใช้ subagent/skill ของโปรเจกต์
skill นี้เก็บทั้งหมดลง **`docs/pm-handoff.md`** ก่อน compact → หลัง compact PM อ่านไฟล์นี้เป็น action แรกแล้วทำงานต่อได้ทันที

## Instructions

1. **กวาดจากบทสนทนาปัจจุบัน** (อย่าเดา — เอาเฉพาะที่เกิดขึ้นจริง):
   - งานที่กำลังทำ + อยู่ขั้นไหนของลำดับ orchestration (skill-PM 2.5) + สถานะ gate ต่าง ๆ
   - สิ่งที่ต้องทำต่อทันที (เรียงลำดับ)
   - **กฎ/การตัดสินใจที่ user กำหนดไว้ระหว่างคุย** ที่ยังไม่ได้เขียนลง docs ไหนเลย — ห้ามตกหล่นเด็ดขาด
   - subagent + skill ที่ใช้ในโปรเจกต์นี้ และเรียกตอนไหน/อย่างไร
2. **เขียนทับ `docs/pm-handoff.md`** ตามโครงด้านล่าง (ไฟล์นี้คือ state ล่าสุดเสมอ — ทับได้ ไม่ต้อง append)
3. **อย่า copy เนื้อหาที่มีใน docs อื่นอยู่แล้ว** — ลิงก์ไปหา (`docs/project-proposal.md`, `docs/data-model.md` ฯลฯ) · ไฟล์นี้เก็บเฉพาะสิ่งที่**อยู่แค่ในบทสนทนา**
4. เสร็จแล้วบอก user สั้น ๆ: **"บันทึก state แล้ว → กด compact ได้เลย · เสร็จแล้วพิมพ์ `/skill-PM` เพื่อทำงานต่อจากเดิม"**

## Rules
- ข้อ 3 (กฎจาก user) สำคัญที่สุด — ตกหล่นแล้วหลัง compact จะทำผิดกฎที่ user เคยสั่ง
- เขียนให้ PM คนใหม่ที่**ไม่เห็นบทสนทนาเดิมเลย**อ่านแล้วทำงานต่อได้ทันที (นั่นคือสภาพหลัง compact จริง ๆ)
- ไฟล์อยู่ `docs/` ตามกฎที่เก็บไฟล์ของ skill-PM
